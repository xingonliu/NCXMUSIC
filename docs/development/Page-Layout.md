# 页面布局与滚动

## 应用外壳

`AppShell` 的纵向滚动画布覆盖整个窗口。外壳不使用 padding 缩小画布，侧边栏以绝对定位覆盖在画布上，保留原来的宽度、外边距、圆角和内部导航布局。侧边栏背景使用现有半透明颜色，并对其背后的页面内容进行模糊。

`ncx-page-frame` 负责正文的顶部留白、左右对齐和播放器底部安全距离，不负责裁切。普通页面不要再叠加页面级顶部 padding。窗口边界由外壳裁切；正文、主视觉与横向列表之间不增加独立的背景面板。

- `--ncx-content-left`：侧边栏右侧正文的起点。
- `--ncx-content-right`：正文右侧间距。
- `--ncx-content-top`：普通页面的顶部安全距离。
- 设置侧边栏保留 260px 宽度；普通侧边栏保留 230px 宽度。
- 窗口未最大化时，侧边栏保留 12px 外边距；最大化与全屏时使用既有零外边距规则。

小云页面继续使用自己的对话滚动容器，外壳读取该容器的纵向滚动状态。侧边栏内部导航仍可独立滚动。

## Header

Header 操作按钮和窗口拖拽区域常驻。材质保持既有浅色、深色渐变及 `backdrop-filter: blur(1px)`，只改变其透明度：页面在顶部时为 0，向下滚动 48px 后为 1，中间按距离连续变化。

路由可以通过 `headerMaterial` 声明 `scroll`（默认）、`transparent` 或 `solid`。页面不直接调用显示或隐藏函数。横向列表、侧边栏和其他子容器的滚动不会改变 Header 状态。

页面切换时记录滚动位置，返回时立即尝试恢复。若详情内容仍在加载，外壳在正文高度变化时继续恢复；用户开始滚动或操作后取消待恢复位置，避免迟到的内容抢走用户位置。

## 音乐详情主视觉

歌手、歌单、专辑、歌曲详情使用 `pageLayout: 'hero'` 和 `MusicDetailHero`。主视觉从窗口顶部开始，横向延伸到侧边栏背后。

主视觉使用一张清晰图片，`object-fit: cover` 允许裁剪；图片不模糊、不另设卡片圆角，正文不重复放置方形封面。没有可用图片时显示中性色背景。渐变遮罩仅用于保证文字可读性。

标题、简介、元信息和按钮统一位于主视觉左下角，左边界与右侧正文起点对齐。主视觉高度随窗口变化，并允许较长内容撑开，确保文字和操作不会被裁掉。歌单和专辑的加载态使用相同的主视觉几何结构。

## Section 与横向列表

`MusicSection` 管理标题、操作、加载、错误和空状态。`layout="rail"` 时，交由 `HorizontalMediaRail` 管理单行卡片及左右翻页。

- 标题、按钮与第一张卡片初始位置对齐正文。
- 横向视口横跨页面，前面的卡片可以滑到侧边栏背后。
- 翻页距离按右侧实际可见宽度计算，不包含被侧边栏遮住的区域。
- 支持原生横向手势、左右按钮和键盘焦点自动露出；普通纵向滚轮不被改成横向滚动。
- 内容不足一屏时不显示方向按钮，到达边界时禁用对应按钮。
- 缩放窗口、内容变化和 KeepAlive 恢复后重新计算边界；组件离开时释放尺寸监听。
- 为封面阴影、悬浮反馈与焦点边框保留空间。

发现页推荐、浏览页专辑/推荐歌单/分类预览/歌手，以及歌手详情中的专辑和相似歌手使用横向列表。完整歌曲、评论、筛选结果和个人资料库保留适合检索的纵向列表或网格。

## 验证

`tests/unit/page-scroll-layout.test.ts` 覆盖 Header 渐显、嵌套滚动隔离、异步滚动恢复、用户操作取消恢复、横向翻页和焦点避让。结构迁移同时维护原有音乐页面与导航测试。

界面验收需覆盖 1280×800 与 960×640 窗口、浅色/深色、窗口最大化、页面顶部与滚动后状态、横滑透底、返回恢复，以及详情主视觉左下角的内容对齐。

# NcxMusic Phase 0～3 未实现项与缺陷修复清单

> 建立日期：2026-08-10
>
> 范围：仅记录代码中尚未实现的能力与已经确认的产品缺陷。
>
> 不包含：自动化测试、测试覆盖率、CI、Lint、构建、API 审计门禁和人工测试计划。

## 1. 状态与优先级

- `P0`：阻断正常账户、写操作或桌面能力，应优先修复。
- `P1`：路线图已声明完成、但代码尚未实现的正式能力。
- `P2`：不会阻断主流程，但会造成状态错误、数据不一致或明显体验缺陷。
- `未实现`：需求已经冻结，但生产代码中没有完整实现。
- `缺陷`：已有代码路径，但实际行为与需求或用户操作结果不一致。

## 2. 用户实测缺陷

### BUG-001 登录成功后个人信息页短暂显示游客资料

- 类型：`缺陷`
- 优先级：`P0`
- 实测现象：
  1. 在未登录状态进入个人信息页。
  2. 打开官方登录窗口并扫码，登录成功后登录窗口自动关闭。
  3. 当前个人信息页显示“游客”，没有立即展示新账号的头像和昵称。
  4. 切换到其他 Tab，再返回个人信息页后，头像和昵称才恢复正确。
- 代码原因：
  - `ProfilePage.vue` 只在 `onMounted` 时执行一次 `loadProfile()`。
  - `window.ncx.account.login()` 在打开登录窗口后就返回当前快照，不会等待扫码登录流程进入最终状态。
  - 全局账户 Store 虽然能收到后续登录成功快照，但个人信息页没有监听 `state`、`accountId` 或 `accountGeneration` 的变化来重新加载资料。
  - 已登录账户的公开快照当前不携带 `displayName` 和 `avatarUrl`。在新账号资料尚未读取时，页面名称计算回退到了“游客”，造成“登录成功后又变成游客”的视觉假象。
- 修复目标：
  - 监听账户状态、账户 ID 和 generation；进入 `authenticated` 或账户发生变化时立即重新读取个人资料。
  - 给异步资料请求绑定账户 ID/generation，丢弃旧账户的迟到响应。
  - 切换期间展示明确的“正在加载账户资料”，禁止使用“游客”作为已登录账号的昵称兜底。
  - 评估在 Main 的安全公开快照中缓存已验证的昵称和头像，作为资料接口完成前的展示值。

### BUG-002 每日签到失败并显示本地服务错误

- 类型：`缺陷`
- 优先级：`P0`
- 实测现象：点击个人信息页的“签到”后没有签到成功，Toast 显示与“本地服务”有关的失败信息；原始完整错误文案尚未记录。
- 已确认代码链路：
  - 页面通过 `music.mutate` 发送 `dailySignin`。
  - Adapter 调用依赖中的 `daily_signin({ type: 1, cookie })`。
  - 依赖当前确实导出了 `daily_signin`，因此不能简单归因于接口不存在。
- 当前风险点：
  - 登录成功广播与 Utility 账户空间切换之间没有“账户已经可执行写操作”的完成回执，用户可能在账户切换尚未完成时发起签到。
  - 凭据租约、Runtime 连接或账户空间尚未就绪时，Renderer 最终只能收到笼统的 `UTILITY_UNAVAILABLE` 文案。
  - 普通异常如果没有保留标准 `code`、HTTP 状态和网易云业务 code，会被降级成“本地服务请求失败”，无法区分未登录、重复签到、上游拒绝和本地运行时错误。
- 修复目标：
  - 为账户切换增加 Utility 就绪确认；在账户空间和凭据租约同时生效后，才把写操作能力标记为可用。
  - 保留并安全映射签到的 HTTP 状态、网易云业务 code 和 Runtime code。
  - 明确区分“签到成功”“今日已签到”“登录已失效”“服务暂不可用”和上游业务失败。
  - 写操作不做透明重试，避免首次请求实际成功但客户端重试导致重复副作用。
  - 个人信息页和发现页复用同一个签到状态与结果处理，避免两个入口表现不一致。

### BUG-003 沉浸歌词页无法复制歌曲信息

- 类型：`缺陷`
- 优先级：`P0`
- 实测现象：点击沉浸歌词页的复制歌曲信息按钮后，界面提示“无法访问系统剪贴板”。截图中的 Toast 为“操作提示 / 无法访问系统剪贴板”。
- 代码原因：
  - 沉浸歌词页直接调用 `navigator.clipboard.writeText()`。
  - 主窗口的 Electron Session 当前拒绝所有 Web 权限请求，Clipboard API 在当前页面上下文中被拒绝。
  - 歌曲行和歌单菜单也存在直接调用 `navigator.clipboard` 的代码，属于同一缺陷面。
- 修复目标：
  - 在 Main/Preload 增加仅允许写文本的窄剪贴板桥，使用 Electron `clipboard.writeText()` 完成系统剪贴板写入。
  - IPC 入参只接受有长度上限的纯文本，不开放剪贴板读取能力，不放开主窗口的通用权限请求。
  - 沉浸歌词、歌曲链接和歌单链接统一使用同一剪贴板桥及成功/失败提示。

## 3. 其他已确认代码缺陷

### BUG-004 登录凭据租约五分钟后静默失效

- 类型：`缺陷`
- 优先级：`P0`
- 当前行为：Main 和 Utility 都把凭据租约最长时间限制为五分钟；到期后只撤销租约，没有续租，也没有把失效状态同步回账户 UI。
- 影响：界面可能继续显示已登录，但高音质解析和所有登录写操作已经退化或失败。
- 修复目标：实现受控续租；续租失败时撤销能力、更新公开账户状态并提示重新登录。续租必须继续保证 Cookie 不进入 Renderer、日志或业务 IPC。

### BUG-005 关闭窗口偏好在重启后没有及时同步给 Main

- 类型：`缺陷`
- 优先级：`P1`
- 当前行为：关闭行为保存在 Renderer `localStorage`，Main 启动时固定使用 `minimize`；只有用户进入设置页或重新修改设置后才向 Main 发送偏好。
- 影响：用户已经选择“关闭即退出”，重启应用后若不进入设置页，关闭按钮仍可能执行最小化。
- 修复目标：在应用启动阶段读取并同步关闭行为，或由 Main 持久化并作为该设置的唯一权威来源。

### BUG-006 退出前播放快照没有完成确认

- 类型：`缺陷`
- 优先级：`P1`
- 当前行为：Renderer 在 `beforeunload`、`pagehide` 中发起异步保存，但保存队列不可等待；Main 的 `before-quit` 会直接关闭账户与 Utility 链路。
- 影响：最后一次暂停、进度、切歌或队列变化可能没有写入 SQLite。
- 修复目标：增加 Main→Renderer flush 请求、Renderer→Main 完成回执和有限超时；收到回执后再关闭 Runtime 与窗口。

### BUG-007 音质降级标记计算错误

- 类型：`缺陷`
- 优先级：`P1`
- 当前行为：首次请求获得可播放 URL、但上游返回的实际档位低于请求档位时，`actualQuality` 可能正确，`downgraded` 仍可能为 `false`。
- 修复目标：以“用户请求档位/自动档位目标”和上游 `actualLevel` 比较，不与已覆盖后的当前值比较；同时返回可展示的降级原因。

### BUG-008 播放快照读取没有执行 generation 规则

- 类型：`缺陷`
- 优先级：`P2`
- 当前行为：保存快照会拒绝旧 generation 写入，读取快照只校验 accountId；代码注释与路线图关于跨登录恢复的规则不一致。
- 影响：同一账号重新登录后可能恢复旧会话快照，也可能与预期的“generation 不一致即丢弃”规则冲突。
- 修复目标：先冻结产品语义，然后统一 Schema、读取逻辑和注释。若允许同账号跨登录恢复，应引入独立的账户会话版本，而不是忽略 generation。

### BUG-009 媒体元素事件没有绑定播放 source generation

- 类型：`缺陷`
- 优先级：`P2`
- 当前行为：URL 解析结果有 generation 防护，但 `<audio>` 发出的 `ended`、`error`、`timeupdate` 等事件没有携带 source 身份。
- 影响：快速切歌时，旧资源的迟到事件可能作用到新曲目，导致错误切歌、错误状态或进度跳变。
- 修复目标：每次装载媒体源生成 source token/generation；领域层只接受当前 token 对应的媒体事件。

### BUG-010 连续媒体失败和播放地址过期处理不完整

- 类型：`缺陷`
- 优先级：`P2`
- 当前行为：连续失败遍历完整个队列后，当前项不一定被清空；播放地址失效也没有独立分类和重新解析路径。
- 影响：播放器可能停留在错误曲目和 `error` 状态，而不是稳定停止；临时 URL 到期后只能跳过歌曲。
- 修复目标：所有候选项失败后清空当前项并进入稳定停止态；把地址过期与资源不可播分开，地址过期允许一次重新解析，资源不可播再执行队列错误策略。

## 4. 尚未实现的冻结需求

### MISS-001 真正的游客匿名会话

- 类型：`未实现`
- 优先级：`P0`
- 当前行为：没有调用 `/register/anonimous`；无正式账户租约时直接使用空 Cookie。
- 缺失内容：匿名 Cookie 建立、独立凭据槽位、恢复与失效、正式账户登录后停用匿名凭据、退出正式账户后重新建立游客会话。
- 同步修复：游客侧栏账户行应显示默认头像和“游客”且不可点击，不能始终跳转个人信息页。

### MISS-002 统一 PlayerCommand 与真实执行回执

- 类型：`未实现`
- 优先级：`P1`
- 缺失内容：共享 `PlayerCommand` Schema、唯一 Gateway、命令 ID、`expectedRevision`、超时、错误码、Coordinator 执行结果和最新快照回执。
- 目标：界面按钮、系统媒体键、后续 Agent 和语音入口全部通过同一个命令入口，不能各自直接修改播放状态。

### MISS-003 播放详情、沉浸歌词和歌曲详情正式路由

- 类型：`未实现`
- 优先级：`P1`
- 当前行为：沉浸歌词使用 App 根层条件覆盖，没有独立 SPA 路由；播放详情和歌曲详情也没有正式路由。
- 缺失内容：路由定义、类型化路由元数据、PlayerBar 显隐、直接访问/返回语义，以及普通、最大化、全屏状态下的一致行为。

### MISS-004 搜索结果的完整歌曲操作

- 类型：`未实现`
- 优先级：`P1`
- 已有：播放、下一首、加入队列、喜欢、复制链接。
- 缺失：加入指定歌单、查看歌曲详情、交给小云，以及这些操作在游客/登录状态下的能力提示。

### MISS-005 账户数据设施的运行时接入

- 类型：`未实现`
- 优先级：`P1`
- 已有：账户 SQLite 路径、`action_journal` 表、播放快照表和 Cache 路径定义。
- 缺失：Action Journal 写入与清理、账户配置持久化、Cache 目录生命周期、账户数据统计，以及“删除此账号的本地数据”完整操作。
- 安全要求：删除必须按明确 accountId 定位，不影响其他账户、登录 Cookie 或可恢复范围之外的数据。

### MISS-006 标准实体池读取闭环

- 类型：`未实现`
- 优先级：`P2`
- 当前行为：Music Service 会把标准实体写入实体池，但业务结果仍直接返回原始归一化对象，生产代码没有通过实体池统一读取。
- 缺失内容：实体查询/合并入口、字段新鲜度策略、账户切换清理或隔离，以及页面读取标准实体的统一路径。

### MISS-007 Design System 关键语义

- 类型：`未实现`
- 优先级：`P2`
- 缺失内容：Dialog/菜单焦点陷阱与焦点恢复、完整键盘导航、背景 inert、基于真实窗口范围的虚拟列表，以及冻结要求的 1.5 秒 Tooltip。
- 当前虚拟列表只截取前 24 项，超出项不会随着滚动进入可见区域。

### MISS-008 首日 i18n 契约

- 类型：`未实现`
- 优先级：`P2`
- 当前行为：大量页面与 Toast 仍直接硬编码中文，只有少量路由文案使用语言表。
- 缺失内容：统一 i18n 实例、稳定 key、参数化错误文案和组件内文案迁移。首版仍只展示简体中文，但文案来源应统一。

## 5. 建议修复顺序

1. 修复 `BUG-001`～`BUG-004`，先恢复登录后资料刷新、签到和剪贴板等直接用户问题，并消除五分钟凭据失效。
2. 完成 `MISS-001`，统一游客、正式登录、退出与再次登录的账户状态。
3. 修复 `BUG-005`～`BUG-010`，收口桌面设置、持久化和播放状态正确性。
4. 完成 `MISS-002`～`MISS-004`，补齐 Phase 3/4 对外功能入口。
5. 完成 `MISS-005`～`MISS-008`，收口账户数据、实体池和界面基础设施。

以上项目完成前，不应再把 Phase 0～3 标记为完整 `pass`；已经可正常使用的功能不重复列入本清单。

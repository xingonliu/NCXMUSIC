> 文档状态：Draft 0.3（需求访谈进行中）
> 建立日期：2026-08-03
> 最后更新：2026-08-04
> 文档用途：作为产品、设计、架构、开发和验收的唯一需求基线
> 规则：明确区分“已确认”“暂定方案”“待确认”，未经确认的内容不得直接当作开发结论

## 1. 产品概述

### 1.1 一句话定义

NcxMusic 是一款以网易云音乐数据为基础，具备长期用户画像、自然语言和语音操控、Dynamic Skill/MCP 扩展能力，并由确定性权限系统保护的跨平台 Agent 原生音乐客户端。

### 1.2 产品愿景

用户不再需要逐层寻找歌曲、歌单和功能入口，而是可以直接表达目的：

- “播放一些适合今晚写代码的歌。”
- “把当前歌曲加入我的跑步歌单。”
- “分析一下我最近的音乐口味变化。”
- “找出我收藏过但一年没有播放的歌曲。”
- “执行签到，并告诉我结果。”

Agent 不只是回答问题，而是理解上下文、选择工具、执行操作、反馈结果，并在长期使用中形成稳定的用户记忆。

### 1.3 核心产品原则

1. Agent 是一级交互入口，不是播放器上的附属聊天框。
2. 模型负责理解与决策，权限由确定性代码控制。
3. 所有外部能力必须经过统一工具执行入口。
4. 模型不得猜测歌曲、歌单、歌手或用户 ID。
5. 原始 API 字段不得直接扩散到 UI、画像和 Agent 层。
6. 用户数据、本地记忆和安全设置默认按账户隔离。
7. 动态扩展必须可控、可停用、可追踪、可撤销。
8. 每个 API 必须先测试和分析字段，再进入业务开发。

| C-032 | 首次引导中的网易云登录位于模型配置之前，并允许跳过。 |
| C-033 | 跳过网易云登录后，应用在本地调用 `/register/anonimous` 建立游客会话。 |
| C-034 | 游客状态下个人信息不可用；侧栏底部展示默认头像和“游客”。 |

| C-039 | 页面采用 Section 化组合结构，每一块内容是可独立开发、加载、失败和刷新复用的组件。 |
| C-040 | 登录用户完成模型配置且用户画像可用后，首页展示“小 N 为你推荐”Section。 |
| C-041 | 小 N 只提供一个连续会话，不设计多会话列表；跨时间使用依靠长期记忆延续。 |
| C-042 | 用户超过 10 分钟未发送消息时结束当前会话块；每个会话块独立存入 SQLite 并生成摘要。 |
| C-043 | 会话块、摘要和必要原文持久化到 SQLite；系统提示词只装配当前块和本轮选出的高价值长期记忆。具体检索方案待定。 |
| C-044 | 使用独立 Working Memory 文件保存当前块和本轮选中的长期记忆，详细历史按需查询 SQLite。 |
| C-045 | 小 N 触发播放、切歌或队列变化时，显示轻量消息提示，明确操作来自小 N。 |
| C-046 | 前端建设完整的通用组件体系，覆盖基础控件、反馈、浮层、布局和音乐业务组件。 |
| C-047 | 首次画像分析不静默执行；在小 N 输入框上方显示轻量初始化提示，由用户主动开始。 |
| C-048 | 画像增量更新按启动时的加权变化量检查：喜欢歌曲每首权重 1.5，自建歌单歌曲每首权重 1，收藏歌单不计；累计变化超过 30 时提示更新。 |
| C-049 | 小 N 可以通过 `mcp_manager` 发起 MCP Server 安装，但每一次安装都必须弹出批准/拒绝卡片并取得当次明确同意；拒绝时底层安装逻辑零执行。 |
| C-050 | 所有 Agent 审批卡片只提供“批准”“拒绝”，不提供“仅本次允许”“本会话允许”或“总是允许”等额外授权范围；需要减少审批时只能调整音乐/命令安全等级。MCP 安装仍不受任何等级豁免。 |
| C-051 | Electron Main 负责窗口、登录 Session、Credential Vault、进程监督和安全 IPC；Agent Runtime、NeteaseCloudMusicApiEnhanced、MCP、Dynamic Skill、权限中间件与 Shell Executor 运行在独立 Utility Process。 |
| C-052 | Renderer 与本地后端不建立 SSE/localhost 服务；模型增量、工具状态和审批事件通过 Electron IPC/MessagePort 传递。Provider 上游可使用其原生流式协议，但必须在 Utility Process 内归一化。 |
| C-053 | Renderer 使用 Vue 单页应用；唯一 `<audio>` 与播放引擎挂载在 AppShell 根层并位于路由页面之外，路由切换不得销毁音频或中断播放。 |
| C-054 | 音乐控制 Bar 的可见性由 Vue Router 页面元数据统一控制：设置页和个人信息页隐藏；主导航、歌单次导航，以及歌单/歌手/专辑列表与详情页展示。隐藏 Bar 不等于暂停播放。 |
| C-055 | 小 N 的播放目标解析为单曲时，将歌曲插入正式播放队列的当前项之后并立即切换播放；该歌曲作为普通队列项保留。解析为歌单时使用该歌单替换当前队列。 |
| C-056 | 在歌单、专辑、“我喜欢”和歌手热门歌曲等集合详情中点击歌曲行，按列表上下文播放：完整列表替换队列并从点击项开始。小 N 精确点播、全局搜索单曲和推荐单曲卡片仍按单曲临时插播。 |
| C-057 | “上一首”始终切换歌曲，不根据当前播放时长重播当前歌曲；所有模式都切到当前可见队列的上一项。 |
| C-058 | 应用重启后恢复上次播放队列、当前歌曲、当前进度、音量、静音和播放模式，但保持暂停且不得自动出声；播放 URL 不持久化，恢复时按歌曲 ID 重新获取。 |
| C-059 | 首版播放模式只提供列表循环、单曲循环和随机播放，三者互斥；默认使用列表循环，不提供播完末项后停止的顺序播放模式。 |
| C-060 | 歌曲最终判定不可播放时显示轻提示并自动切到下一首；不能用模态框或错误页阻断播放器。 |
| C-061 | 歌单、专辑等歌曲列表 Item 对 VIP 歌曲显示 `VIP` 小标，对单独付费歌曲显示“付费”小标；标记不置灰、不禁用点击，其他版权状态首版不增加列表标记。 |
| C-062 | 删除非当前队列项不影响播放；删除当前项立即切到删除后接替的下一项，删除末项时回到第一项；仅剩一项时删除或清空队列均立即停止播放。 |
| C-063 | 首版播放队列不提供撤销；删除、清空、替换和重排即时生效，小 N 操作只显示轻提示和影响数量。播放队列变更不等于修改网易云歌单。 |
| C-064 | 进入随机播放时直接打乱当前可见队列，并从打乱后的第一首开始播放。不保留隐藏的原始顺序或随机顺序；用户拖动后继续按当前可见列表播放。 |
| C-065 | 按住 `Alt+Space` 进入语音聆听时，当前音乐不暂停，而是临时降低到原输出约 20%；松手后恢复。期间如果用户或小 N 执行了暂停、切歌等新播放意图，则不恢复旧播放状态。 |
| C-066 | “关闭窗口时”设置仅提供“最小化窗口”和“退出应用”两个选项，默认为最小化窗口。默认状态下点击关闭按钮仍继续后台播放；选择退出应用时则终止进程和播放。 |
| C-067 | 首版语音能力只做 ASR 语音识别与指令输入，不做 TTS 语音合成或语音播报。 |
| C-068 | Agent 不调用 Vue 组件函数，也不通过内部 SSE 间接操作 Pinia。Agent Tool 经权限中间件后通过 IPC/MessagePort 发送版本化 `PlayerCommand`，由 Renderer 根层常驻处理器调用唯一 `PlaybackCoordinator`，并将真实执行结果和最新快照回传给 Tool。 |
| C-069 | 播放设置提供全局音质偏好，包含“自动（最高可用）”和 NeteaseCloudMusicApiEnhanced 当前文档列出的 9 个 `level`：`standard`、`higher`、`exhigh`、`lossless`、`hires`、`jyeffect`、`sky`、`dolby`、`jymaster`。 |
| C-070 | 默认使用“自动（最高可用）”，只在常规高保真链中按当前账户权益和歌曲实际音源选择最高可播档位；高清环绕声、沉浸环绕声和杜比全景声必须由用户明确选择。具体音质作为所有歌曲的全局偏好上限；单曲、账户或设备不支持时自动回退到可播音质，不因偏好档位不可用而跳过歌曲。 |
| C-071 | 播放过程中修改全局音质后，立即为当前歌曲解析新媒体源并尽量保持播放进度。切换前正在播放则新源就绪后继续播放，切换前暂停则保持暂停；允许一次短暂缓冲，不从头重播。 |
| C-072 | 首版源码采用“单仓库、单应用包、模块化单体”，不预先拆分多个 workspace package。通过 Main、Preload、Renderer、Utility 进程入口，业务领域、共享契约和基础设施目录及 import 规则强制边界；达到独立发布或复用条件后再拆 workspace。 |
| C-073 | Renderer 是单页面应用，应用内页面切换全部通过 Vue Router 完成，不以重载窗口或新建 BrowserWindow 代替导航。歌单、专辑、歌手、歌曲等二级页面统一在 PageHeader 左侧提供返回按钮：优先返回有效的应用内路由历史；直接打开且无可返回历史时回退到该页面定义的稳定父级路由。 |
| C-074 | 前端建立单一 Design System：所有页面只通过 Design Tokens、通用组件、布局模式和领域组件构建，不允许业务页面复制按钮、Header、浮层、消息反馈或直接定义另一套视觉常量。 |
| C-075 | 首版统一提供 Button/IconButton、表单控件、Toast、Dialog、AlertDialog、Drawer、Popover、菜单、Tooltip、加载/空/错状态等通用组件；浮层按任务语义选择，审批不能降级成 Toast 或普通确认弹窗。 |
| C-076 | PageHeader 是一级与二级页面的唯一标准 Header；二级页面返回行为由路由元数据驱动。业务页面的按钮必须使用统一 Button/IconButton，并完整覆盖 Hover、Pressed、Focus、Disabled 和 Loading 状态。 |
| C-077 | 前端使用 Reka UI 作为无样式、可访问交互 Primitive，但只能由 NcxMusic Design System 的内部适配层导入。业务页面和领域组件只使用项目自有组件 API，不直接依赖、透传或暴露 Reka UI 类型；全部外观、Token 和产品语义由 NcxMusic 控制。 |
| C-078 | 跨进程通信由 Main 的 ConnectionBroker 建立版本化 MessagePort 通道；所有请求、响应、事件和取消消息使用 Zod 严格 Schema 校验。Renderer 重载或 Utility Process 重启后建立新连接并拉取快照；有副作用命令使用 `commandId` 去重，不能因重连重复执行。 |
| C-079 | 应用持久数据写入 `app.getPath('userData')/ncx-data`，画像、长期记忆、聊天和账户数据按网易云用户 ID 隔离，以普通 SQLite/JSON 保存，不使用 SQLCipher、独立账户数据密钥或整库加密。Cookie、模型 API Key、MCP 凭据等可登录账号或产生费用的秘密仍必须使用持久 Session 或系统 `safeStorage` 保护。 |
| C-080 | NcxMusic 不上传原始本地数据库或无关账户文件；但使用云模型时，当次对话以及被上下文选择器选中的必要画像/记忆片段会发送给用户配置的模型 Provider。产品必须在配置与画像初始化时明确披露该边界，不能宣称所有 Agent 数据永不离开本机。 |
| C-081 | 手写 Agent Runtime 使用确定性 Turn/Tool 状态机：单会话同时只有一个 Active Turn；只读且互不依赖的工具最多并行 4 个，播放器、账号写入、Shell 和安装等副作用按冲突域串行。单 Turn 最多 12 轮模型/工具循环和 24 个 Tool Call，达到上限后停止工具并生成限额说明。 |
| C-082 | 命令安全采用 S1~S4 四档并提供独立的“关闭 Shell Tool”开关：从全部审批、只读白名单免审、授权工作区开发操作免审，到授权工作区内通过 S4 审查的命令全部免审。Shell Executor 只接收其类型化契约、授权工作区和最小环境中实际提供的能力。 |
| C-083 | 通用按钮明确分为纯文字 Button、纯图标 IconButton、图标+文字 Button。IconButton 默认透明且保持正方形，Hover 时使用主题浅/深灰语义背景与统一圆角；鼠标停留 1.5 秒后显示功能名称和平台快捷键 Tooltip。 |
| C-084 | 生产环境全局接管默认浏览器右键菜单，只对有语义操作的对象和文本编辑上下文展示 NcxMusic ContextMenu；输入框保留完整编辑能力，空白区域不显示网页式菜单。首版按歌曲、队列、歌单、专辑、歌手和 Agent 对象矩阵生成菜单，并包含“交给小 N”子菜单；取消收藏/移除直接执行并 Toast 提示，只有删除自建歌单等不可逆操作使用 AlertDialog。 |
| C-085 | 普通音乐、Shell、Skill 与 MCP 审批均只绑定当前规范化 Tool Call，并只显示“批准”“拒绝”两个按钮。批准不能创建会话级或永久豁免，工具名、参数、目标账号、账户 generation 或 `commandId` 变化后必须重新执行纯函数权限判断。 |

## 3. 目标用户与使用场景

> 本节尚未完成用户访谈，以下用户范围仍为暂定假设；产品形态和开源属性已经确认。

### 3.1 暂定目标用户

- 网易云音乐重度用户，拥有多年歌单和收藏数据。
- 希望通过自然语言降低找歌、整理歌单和操作播放器成本的用户。
- 经常在电脑上学习、工作、创作，需要场景化背景音乐的用户。
- 愿意配置模型、Skill、MCP 或本地自动化能力的进阶用户。
- 偏好高完成度、强视觉表现和桌面原生体验的开源软件用户。

### 3.2 核心场景

1. 自然语言搜索并播放歌曲。
2. 根据长期画像生成符合当前场景的推荐。
3. 对当前歌曲、队列和歌单进行上下文操作。
4. 分析用户口味、性格倾向和近期变化。
5. 通过按住快捷键快速发出语音命令。
6. 使用 MCP、Dynamic Skill 和 Shell 扩展 Agent 能力。

## 4. 核心用户闭环

```text
登录网易云
  → 获取账户与音乐数据
  → 归一化实体和字段
  → 读取或生成用户画像
  → 用户通过文字/语音表达意图
  → 手写 Agent 选择工具
  → 参数与实体解析
  → 确定性权限拦截
  → 自动执行或等待审批
  → 返回结果并更新会话/长期记忆
```

## 5. 功能需求

### 5.1 音乐客户端基础能力

- 账户登录、退出和会话恢复。
- 首页、搜索、歌手、专辑、歌曲、歌单、MV、评论等页面。
- 播放、暂停、上一首、下一首、进度、音量、播放模式。
- 播放队列的增加、移除、清空和重排。
- 收藏/取消收藏歌曲。
- 创建、删除和管理歌单。
- 添加歌曲到歌单、从歌单移除歌曲。
- 评论查看、发表评论及其他互动能力。
- 签到等账户辅助操作。
- 首版不提供支付、购买、订阅、下单或代购能力；相关接口不得注册为内置 Tool，也不得通过通用 API Gateway 暴露。

#### 播放目标与队列语义

已确认按照“集合上下文”和“独立单曲”区分入口：

| 播放目标 | 队列行为 |
| --- | --- |
| 单曲 | 插入并立即播放：非空队列中插到当前项之后，随后把当前项切换到新歌曲；空队列中插为第一项。歌曲进入正式队列，不使用队列外临时层，也不在播放后自动移除。 |
| 歌单 | 使用歌单歌曲建立新队列并替换当前队列；未指定起始歌曲时从歌单第一首开始。 |
| 集合详情中的歌曲行 | 在歌单、专辑、“我喜欢”和歌手热门歌曲等详情中点击一首歌时，用当前完整列表替换队列，并从点击项开始。 |
| 脱离集合上下文的单曲 | 小 N 精确点播、全局搜索结果中的单曲、推荐单曲卡片均临时插播。 |

连续点播单曲时，每首新歌都插在当前项之后并立即播放，因此按发生顺序保留在正式队列中。“上一首”每次都直接切歌，不按 3 秒/5 秒等阈值重播当前歌曲；被切走歌曲不保存独立续播进度。搜索或推荐 Section 的“播放全部”如何建立列表上下文仍待确认。

#### 应用重启恢复

应用退出前持久化一份播放现场快照：正式队列、当前队列项、当前歌曲进度、音量、静音和播放模式。启动后先恢复队列和控制栏状态，再按歌曲 ID 重新获取可播放 URL；媒体元数据就绪后定位到保存进度，但播放意图固定为暂停，用户主动点击播放后才继续。

播放 URL、Cookie 和每首历史歌曲的独立进度不进入播放快照。快照按账户隔离并包含 Schema 版本；具体写入节流、过期周期和当前歌曲已不可播放时的交互仍待技术设计。

#### 音质设置与逐曲回退

截至 2026-08-04，[NeteaseCloudMusicApiEnhanced 官方文档](https://neteasecloudmusicapienhanced.js.org/) 为 `/song/url/v1` 列出以下 `level`：

| API level | 设置页名称 | 类型 |
| --- | --- | --- |
| `standard` | 标准 | 常规音质 |
| `higher` | 较高 | 常规音质 |
| `exhigh` | 极高 | 常规音质 |
| `lossless` | 无损 | 常规音质 |
| `hires` | Hi-Res | 高解析音质 |
| `jyeffect` | 高清环绕声 | 特殊空间格式 |
| `sky` | 沉浸环绕声 | 特殊空间格式 |
| `dolby` | 杜比全景声 | 特殊空间格式 |
| `jymaster` | 超清母带 | 高规格音质 |

- 音质选择是持久化的全局播放偏好，不在队列中为每首歌复制一份设置。
- 默认“自动（最高可用）”；自动只在 `jymaster → hires → lossless → exhigh → higher → standard` 常规高保真链中选择。游客/普通用户、VIP、已购买单曲和不同歌曲均以当次请求的实际可播结果为准，不用前端 VIP 小标推断上限。
- 用户选择具体档位时，该档位是首选上限。若当前歌曲或账户无权播放，`TrackResolver` 向下回退并保存最终 `actualLevel`；设置为极高、但单曲最高只有较高时，应直接播放较高。
- `jyeffect`、`sky` 和 `dolby` 不进入自动链，只在用户明确选择时请求。它们需要设备/编解码支持，选中而不可用时回退到当前账户可用的最高常规音质。
- 音质降级本身不显示错误。播放 UI 使用 `actualLevel`，不把用户偏好误标为当前实际音质。
- 播放中修改音质会立即作用于当前歌曲：新设置先持久化，再后台解析新源；新源就绪前不主动停掉仍可播放的旧源。
- 切换新源时取交换时的最新进度和播放/暂停意图：原先播放则 seek 后继续，原先暂停则 seek 后保持暂停。若解析期间用户已切歌或再次修改音质，旧解析结果必须丢弃。
- 若最终 `actualLevel` 与当前媒体源完全相同，只更新偏好和 UI，不做无意义的重载。网络失败导致新源无法解析时，保留旧源播放并轻提示，新偏好从下一次成功解析继续生效。

官方文档与仓库类型目前存在差异：在线文档包含 `higher` 和 `dolby`，但 [`interface.d.ts`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/main/interface.d.ts) 的 `SoundQualityType` 暂未包含两者；[`song_url_v1.js`](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/main/module/song_url_v1.js) 也明确说明 `unblock=true` 时音质设置不生效。实现时在 NcxMusic API Adapter 内维护已验证的本地枚举，不让上游类型漏项限制 UI；每个档位仍必须先通过 API First 实测。

#### 不可播放与权益标记

- 歌曲在当前账户下最终无法获取或播放 URL 时，通过轻量 Message/Toast 说明不可播放，并自动切换到下一首。
- VIP、付费、已下架或地区限制等原因不能使用模态框阻断播放流程。
- 为避免列表循环或单曲循环产生无限跳转，同一轮自动跳歌不重复尝试已经失败的队列项；整轮没有可播放歌曲时停止并显示轻提示。
- 统一 `TrackRow` 在歌单、专辑等歌曲列表中支持权益小标：会员权益歌曲显示 `VIP`，需要单独购买的歌曲显示“付费”。
- 权益小标只是信息展示，不代表当前账户一定不能播放，也不能用于前端直接拦截点击；是否可播以当前账户实际 URL 获取和播放结果为准。
- 其他版权状态首版不在列表 Item 增加标记。VIP、付费及当前账户已购状态的原始字段必须先通过 NeteaseCloudMusicApiEnhanced 样本测试，再映射到统一 `accessBadges`，不得在 UI 中直接判断原始 `fee`/`privilege` 等字段。

#### 封面图片尺寸与清晰度

截至 2026-08-04，[NeteaseCloudMusicApiEnhanced 官方文档](https://neteasecloudmusicapienhanced.js.org/) 明确支持在网易云图片链接上使用 `?param=宽y高` 控制返回尺寸，例如 `?param=200y200`。首版只依赖已明确的尺寸能力，不假设存在独立图片质量参数。

方形歌曲、专辑、歌单和歌手图片由统一图片 URL Adapter 生成以下语义变体：

| 变体 | 请求尺寸 | 主要场景 | 加载策略 |
| --- | ---: | --- | --- |
| `thumbnail` | 96 × 96 | TrackRow、搜索建议、播放队列、密集历史列表 | 懒加载；长列表配合虚拟化 |
| `compact` | 160 × 160 | PlayerBar、小型实体行、轻量消息中的歌曲封面 | 当前播放项优先，其余按需 |
| `card` | 320 × 320 | 普通专辑、歌单、歌手网格卡片 | 首屏优先，屏外懒加载 |
| `feature` | 640 × 640 | 首页推荐卡片、“小 N 为你推荐”等重点推荐 Section | 进入可视区域前预取，保证高 DPI 清晰度 |
| `hero` | 1024 × 1024 | 歌曲/专辑/歌单详情、Now Playing、播放歌词页的大封面 | 当前实体优先加载；不用无尺寸原图重复请求 |

- `MediaArtwork` 只接收原始 `sourceUrl` 和语义 `variant`，页面组件不得传任意请求像素或手写查询字符串。
- Adapter 使用 URL API 设置或替换唯一的 `param=<width>y<height>`，保留其他合法查询参数；标准实体池只保存原始图片 URL，不把派生尺寸 URL 反写为权威字段。
- 推荐与详情使用“适合其显示尺寸的最高精度变体”，不是无条件下载 CDN 原图；原图小于目标尺寸时不假设服务端能够无损放大。
- 加载失败时保留布局尺寸并显示统一占位图；不能因高精度图失败而让整个 Section 失败。必要时可回退到较低一级变体，但不得无限重试。
- 缓存键必须包含规范化原图地址和尺寸变体；封面缓存属于可重建 Cache，不进入账户持久数据备份。

#### 队列删除与清空

- 删除非当前歌曲只更新队列，不中断当前播放。
- 删除当前歌曲时立即停止当前媒体流，并播放删除后占据同一位置的下一项。
- 当前歌曲位于队列末尾且删除后仍有歌曲时，回到队列第一项；单曲循环不能阻止本次切换。
- 随机播放不建立隐藏播放序列；删除当前歌曲时，同样播放可见队列中删除后占据同一位置的接替项。
- 队列只剩当前一首时删除，或用户执行清空队列时，立即停止播放、清除媒体源并进入空队列状态。
- 首版删除、清空、替换和重排均不提供撤销。播放队列只是临时播放状态；真正修改网易云歌单必须调用独立歌单工具并经过对应权限策略。

#### 随机播放与队列排序

- 用户切换到随机播放时，立即打乱整个当前队列，在队列面板中显示打乱后的真实顺序，并从新队列第一首开始播放。
- 播放器只维护一份可见且真实生效的队列，不在背后同时保留“原始列表”、“随机列表”或专用的上一首历史。
- 随机状态下允许用户删除、新增和拖动队列项；调整后不退出随机模式，上一首、下一首和自然连播都按当前可见列表执行。
- 切回列表循环只改变播放模式，不恢复洗牌前顺序。随机模式播完一轮后，下一轮重新洗牌。

> 产品不以完整复刻网易云官方客户端为目标，但“高颜值播放器”首版的准确页面与能力边界仍待确认。

#### 首版页面范围

- 发现页：首页内容、推荐、最近播放和快捷入口。
- 搜索页：搜索输入、建议、历史、分类结果和结果操作。
- 歌单详情页：歌单信息、歌曲列表、播放和歌单操作。
- 专辑详情页：专辑信息、歌曲列表、收藏和播放。
- 歌手详情页：歌手信息、热门歌曲、专辑及相似/推荐歌手。
- 播放详情页：当前歌曲、封面、播放控制、歌词和队列入口。
- 独立歌词沉浸态：大歌词、背景视觉和全屏体验。
- 小 N：Agent 会话、工具执行和审批交互。
- 我的音乐：我喜欢的音乐、自建歌单、收藏歌单及后续音乐资产。
- 账户页：网易云账户信息、画像摘要和账户操作。
- 设置页：模型、Agent、MCP、Skill、安全、播放、外观和存储设置。

#### Section 化页面结构

所有聚合页面由独立 Section 组件拼接，不在单个页面组件内直接堆叠接口和业务逻辑。

```text
PageShell
  ├─ PageHeader
  ├─ Section A
  ├─ Section B
  ├─ Section C
  └─ PlayerSafeArea
```

Renderer 采用 Vue SPA。`AudioHost`、唯一 `<audio>` 和播放领域实例挂载在 AppShell 根层，`RouterView` 只替换页面内容：

```text
Vue AppShell
  ├─ AudioHost（始终挂载，不参与路由切换）
  ├─ SidebarLayout
  │    └─ RouterView / PageShell / Sections
  ├─ PlayerBar（按 route.meta.playerBar 显示或隐藏）
  └─ 全局 Overlay / Toast / Dialog
```

PlayerBar 是播放引擎的控制视图，不拥有播放状态。隐藏或卸载 PlayerBar 只能移除控制界面和 `PlayerSafeArea`，不能调用 `pause()`、清空队列或销毁 `AudioHost`。

| 页面类型 | PlayerBar |
| --- | --- |
| 发现、搜索、小 N 等主导航页面 | 展示 |
| 我喜欢、自建歌单、收藏歌单等次导航页面 | 展示 |
| 歌单、歌手、专辑列表与详情页 | 展示 |
| 设置页 | 隐藏 |
| 个人信息页 | 隐藏 |
| 首次引导、登录、播放详情/沉浸歌词等其他页面 | 待确认 |

Vue Router 使用类型化 `route.meta.playerBar: 'show' | 'hide'` 作为唯一判断来源；嵌套路由可由父布局给出默认值、叶子路由覆盖。禁止在各页面复制路径判断或直接操纵全局 PlayerBar。

应用内页面跳转统一由 Vue Router 管理，不能通过刷新 Renderer、新建业务窗口或手工替换 URL 实现。一级导航页面的 `PageHeader` 不显示返回按钮；由内容进入的歌单、专辑、歌手、歌曲等二级页面统一显示返回按钮。返回行为优先消费有效的应用内路由历史；若用户通过协议链接、恢复状态或其他直接入口打开二级页且没有应用内上一页，则按路由配置的 `meta.fallbackRoute` 返回稳定父级页面。弹窗、抽屉和上下文菜单不视为二级页面，不占用页面返回历史。

每个 Section 必须独立声明：

- Section ID、标题和展示条件。
- 数据依赖和缓存键。
- Loading、Empty、Error、Ready 状态。
- 刷新、重试和取消能力。
- 最小高度与响应式布局。
- 埋点和错误边界。

一个 Section 请求失败不能阻断整个页面。Section 支持配置排序、按条件隐藏和后续灰度扩展。

首页暂定 Section：

- 继续播放/最近播放。
- 每日或平台推荐。
- 小 N 为你推荐。
- 推荐歌单。
- 推荐歌手。
- 其他通过 API 实测后确认的内容。

“小 N 为你推荐”只在以下条件同时成立时展示：

1. 已登录正式网易云账号。
2. 已完成可用的大模型配置。
3. 当前网易云用户 ID 对应的画像状态为 `ready`。

游客、未配置模型或画像尚不可用时不展示空壳 Section，避免首页出现无意义占位。

暂定“小 N 为你推荐”为常规展示模块且不自动播放；用户点击后开始播放。用户明确表达“随便放点歌”等开放式意图时，是否授权小 N 自主选歌并立即播放仍待确认。

#### Codex 式双层侧栏（已确认）

侧栏拆分成两个语义明确的区域：主导航负责切换产品能力，次导航负责让用户尽快听到自己的音乐。

```text
┌─────────────────────┐
│ 主导航（顶部固定）    │
│   发现               │
│   搜索               │
│   小 N               │
├─────────────────────┤
│ 歌单次导航（中部弹性） │
│   我喜欢             │
│   我创建的歌单        │
│     最近/置顶的 5 个   │
│     查看全部          │
│   我收藏的歌单        │
│     最近/置顶的 5 个   │
│     查看全部          │
│                     │
│   内容超长时仅本区滚动  │
├─────────────────────┤
│ 头像 + 用户名（第一行） │
│ 设置按钮（第二行）     │
└─────────────────────┘
```

次导航包含“我喜欢 + 我创建的歌单 + 我收藏的歌单”，使用折叠、置顶和数量限制控制长度，而不是把所有歌单永久铺开：

- “我喜欢”固定第一位，单击直接进入并可立即播放。
- “我创建的歌单”默认展开，优先显示置顶或最近播放的 5 个歌单。
- “我收藏的歌单”默认折叠，展开后同样只显示置顶或最近播放的 5 个歌单。
- 两组歌单均提供“查看全部”，进入完整音乐库页面。
- 用户可以置顶、取消置顶和调整同组歌单顺序。
- 次导航区域独立滚动，不挤压主导航与底部账户区。
- 歌单数据从本地缓存优先恢复，后台增量刷新，避免启动时等待全部接口。

布局约束：

- 主导航高度由内容决定，不参与滚动。
- 底部账户区固定在侧栏底部，不参与滚动。
- 次导航占据两者之间的剩余高度，必须设置最小高度为 0，并只在自身范围内纵向滚动。
- 次导航内容不得覆盖、挤出或推动底部账户区。
- 账户行展示头像和用户名；设置行单独展示设置入口，保持两行结构。

选择三类内容的原因：收藏歌单同样是用户高频播放资产，完全隐藏会增加路径；直接全部展开又会让重度用户侧栏失控。折叠和最近/置顶策略可以同时解决两者。

其他规则：

- “主页”建议命名为“发现”，表达推荐、最近播放和内容探索。
- 个人信息通过侧栏底部账户区进入，不占用主导航。
- 歌单、专辑、歌手和歌曲详情是由内容进入的二级路由。
- “歌手推荐”作为发现页内容模块和二级列表页。
- 歌曲详情与歌词优先合并为“播放详情”的不同展示态。

该信息架构、次导航内容和默认折叠规则已确认。

### 5.2 官方网页登录与 Cookie 会话

#### 已确认登录方向

1. 用户点击登录后，NcxMusic 打开独立、隔离的官方网易云网页登录窗口。
2. 登录页面由网易云提供，NcxMusic 不创建手机号、密码或验证码输入表单。
3. 主进程监听登录 Session 的 Cookie 变化，只在网易云相关域名中查找 `MUSIC_U`。
4. 捕获到 `MUSIC_U` 后，不立即把“拿到 Cookie”视为登录完成。
5. Node.js API Adapter 使用 `cookie: "MUSIC_U=<value>"` 调用 `/login/status` 或 `/user/account`。
6. 只有验证成功并获得稳定网易云用户 ID 后，才进入已登录状态并关闭登录窗口。
7. 本地记忆、画像、缓存和设置随后切换到该网易云用户 ID 对应的账户空间。

#### Credential Vault

`MUSIC_U` 等同于长期登录凭据，必须遵守：

- 网易云官方登录使用独立持久 Session Partition；其中的 Cookie Store 是 `MUSIC_U` 等网页登录 Cookie 的权威持久来源，不再把同一 Cookie 复制到普通 JSON 或另一份凭据文件。
- 只允许 Electron Main 读取登录 Session Cookie。Main 通过专用控制通道向经过授权的 Utility Process API Adapter 发放当前账户的内存凭据租约，租约不得进入业务 IPC。
- Renderer、Agent Prompt、模型请求、Tool Call 参数和 IPC 业务事件均不得包含原值。
- 模型 API Key、MCP Secret 等非 Cookie 凭据使用操作系统 `safeStorage` 加密后落盘；不以明文 JSON、LocalStorage 或普通配置文件保存。若系统加密不可用，只允许会话级使用并明确提示，不得静默降级成明文持久化。
- 日志中只允许记录“是否存在、校验状态、过期状态”，禁止记录原值或可逆片段。
- API Adapter 在请求发出前从内存租约读取允许的 Cookie，并在内部构造 Cookie 参数。
- 优先通过 POST body 的 `cookie` 字段传递，避免凭据出现在 URL、代理日志和历史记录中。
- 退出登录时清除登录 Session、内存凭据租约和 API 会话缓存；默认保留该网易云用户 ID 的画像、记忆与聊天数据，只有用户执行“删除此账号的本地数据”时才移除账户空间。
- 任何本地凭据、调试样本和登录 Session 文件都必须排除在 Git 之外。

#### 登录窗口安全边界

- 登录窗口使用独立 Session Partition，不和主应用页面共享任意 Web 权限。
- 登录窗口关闭 Node Integration，开启 Context Isolation 与 Sandbox。
- 只允许网易云登录所需域名；新窗口、下载、外部协议和非预期导航默认阻止。
- 登录页面不得获得 NcxMusic 的 Agent、Shell、MCP、文件或播放器 IPC 权限。
- 登录超时、用户关闭、Cookie 校验失败和账号切换必须有明确状态。

#### 暂定状态机

```text
logged_out
  → opening_official_login
  → waiting_for_cookie
  → validating_cookie
  ├─ authenticated
  ├─ validation_failed
  └─ cancelled

authenticated
  → session_expired
  → opening_official_login
```

#### 游客会话

用户在首次引导中跳过网易云登录时：

1. 本地 API Adapter 调用 `/register/anonimous` 获取游客 Cookie。
2. 游客 Cookie 进入独立 Credential Vault 槽位，不与 `MUSIC_U` 混用。
3. 应用进入 `guest` 会话，可使用搜索、公开内容和游客凭据允许的播放接口。
4. 歌单次导航完全隐藏，不显示置灰的我喜欢、自建歌单或收藏歌单入口。
5. 账户、我喜欢、创建/收藏歌单、用户画像等登录能力不可用。
6. 侧栏底部账户行显示默认头像和“游客”，不伪造网易云用户 ID；第二行设置按钮仍可用。
7. 用户后续完成官方登录后切换到 `authenticated` 会话，游客凭据停止用于请求，并显示歌单次导航。
8. 用户退出正式账户后，重新建立或恢复游客会话，隐藏歌单次导航，播放器仍可继续使用公共能力。

游客登录接口只能改善部分未登录请求的验证问题，不代表游客拥有正式账户的个性化、收藏和写入权限。每个 API 仍需通过真实请求测试确认游客可用性。

当前要求游客账户行点击无效，但跳过登录后必须保留一个明确的二次登录入口。入口位置暂定为设置页“网易云账户”，是否在游客账户行旁增加“登录”按钮待确认。

#### 待实测的登录假设

当前方案假设 NeteaseCloudMusicApiEnhanced 可以接收完整的 `MUSIC_U=xxxx` Cookie 字符串，并通过 `/login/status` 或 `/user/account` 校验登录状态。Cookie 的实际传递位置、游客接口 `/register/anonimous` 的可用性、不同登录态返回字段和失效行为，必须按 API First 规则用当前依赖版本实测后再冻结。

### 5.3 手写 Agent Runtime

Agent Runtime 至少包含：

- 会话消息管理。
- 系统提示词组装。
- Dynamic Skill Prompt 按需注入。
- Tool Schema 注册与模型可见工具裁剪。
- 流式模型响应解析。
- Tool Call 参数校验。
- 多轮工具调用循环。
- 工具结果回填。
- 取消、超时、重试和最大步数控制。
- 审批等待与恢复。
- 会话短期上下文。
- 长期记忆读取与写入。
- 运行事件日志与调试信息。

完整状态机、调度冲突域、计数、取消与恢复规则以 `docs/architecture/NcxMusic-Agent-Runtime.md` 为准。

#### 单会话模型

- 产品只有一个持续存在的小 N 会话入口。
- 不提供“新建会话”、会话列表或并行会话切换。
- UI 展示的是当前活跃会话块；历史内容通过时间分隔、搜索和记忆召回使用。
- 关闭应用后恢复当前未结束的会话块和 Working Memory。

#### 会话分块规则

SQLite 是消息和会话块的事实来源。用户最后一次发送消息后超过 10 分钟，再次发送消息时创建新块，并将上一块标记为完成。

每个会话块至少包含：

```text
blockId
neteaseUserId / guestInstallationId
startedAt
lastUserMessageAt
endedAt
messages
toolCallRefs
summary
summaryImportance
searchKeywords
status
```

分块结束后异步生成摘要；摘要失败不影响新块继续聊天，但需要进入重试队列。每个块都必须最终拥有摘要，才能进入长期记忆检索。

#### Context Assembler

模型请求不直接装入全部 SQL 历史，而由 Context Assembler 组装：

```text
System Rules
+ Dynamic Skills
+ User Profile
+ Current Working Memory
+ 当前会话块的必要消息
+ 检索命中的高价值历史摘要
+ 当前播放器/页面上下文
```

Working Memory 文件是可重建的 Prompt 快照，不是历史事实来源。建议按网易云用户 ID 隔离，保存：

- 当前 block ID。
- 当前块仍需进入上下文的消息引用或裁剪内容。
- 本轮选中的长期摘要 ID。
- 用户当前目标、未完成事项和重要临时事实。
- 上次成功写入时间与 Schema 版本。

Working Memory 采用原子替换写入；损坏或版本不兼容时从 SQLite 重建。文件不保存 API Key、Cookie 或 Shell 敏感输出。

#### 长期记忆检索（待定）

已经确定的是存储和上下文边界：

- 每个完成的会话块生成结构化摘要和可检索文本。
- 摘要标注人物、偏好、承诺、任务、音乐实体、时间和重要性。
- 会话块、摘要、必要原文和结构化标签持久化到 SQLite。
- Agent 通过稳定的 `memory_search` Tool 查询，检索后端不能泄漏到 Prompt 和业务工具协议。
- 原始消息默认不直接进入长期 Prompt，只有明确需要细节时读取。
- 召回结果必须综合相关性、重要性、新鲜度和冲突检查。

候选方案包括 SQLite FTS、向量检索，以及先结构化过滤再组合全文与向量召回的混合检索。最终方案需用真实中文会话测试集比较准确率、语义召回、安装体积、离线能力、隐私、成本和迁移复杂度后确认；当前文档不指定首版采用其中任何一种。

### 5.4 Agent Tool 分层

#### 高级业务工具

首版模型可见的内置核心业务 Tool 冻结为 10 个：

| Tool | 主要职责 |
| --- | --- |
| `smart_search_and_play` | 搜索、实体解析、获取播放资源并发起播放；歧义时返回 `needs_selection`，不静默猜测 |
| `control_player` | 获取播放状态，以及播放/暂停、上下首、进度、音量和播放模式 |
| `queue_manager` | 查看、插入、下一首播放、移除、排序、替换和清空当前队列 |
| `playlist_manager` | 查看、创建、重命名、删除歌单，以及增删/排序歌单歌曲 |
| `library_manager` | 喜欢/取消喜欢，以及收藏/取消收藏歌曲、专辑、歌手或歌单 |
| `music_explorer` | 搜索与查看歌曲、歌手、专辑、歌单、歌词、相似内容和推荐内容 |
| `comments_and_social` | 查看/发布/删除评论、评论点赞，以及关注/取消关注 |
| `account_manager` | 登录态与账户资料、签到、允许范围内的资料修改和退出登录；不包含支付购买 |
| `user_profile_memory` | 读取/生成/更新音乐画像，以及查询允许进入上下文的长期记忆 |
| `request_user_selection` | 向用户展示无副作用的单选/多选快捷问题并返回答案 |

每个 Tool 使用判别式 `action` Schema；Tool 名相同不代表动作的读写性质、冲突域或 M 等级相同。Runtime 必须在参数归一化后按具体 action 分类。

#### 原子音乐工具

- 搜索歌曲/歌手/专辑/歌单。
- 获取歌曲详情、URL、歌词。
- 获取/修改歌单。
- 收藏/取消收藏。
- 获取/发布评论。
- 获取当前播放状态。

#### 通用 API Gateway

仅在没有专用工具时使用。兜底能力由两个 Tool 组成：

- `find_music_api_capabilities`：只读检索 Capability Catalog，按用户意图返回少量匹配的 `capabilityId`、用途、所需实体引用和参数契约；不调用网易云业务接口。
- `call_music_api`：接收已经发现的 `capabilityId` 和参数，通过对应 Schema、实体解析与 Policy 后调用内部 Adapter。

Gateway 必须具备：

- 正向 Music API Capability 清单；每项由稳定 `capabilityId` 映射内部 API 路径和参数 Schema，不向模型开放任意 `path: string`。
- 参数 Schema 校验。
- 登录态和账户权限校验。
- 风险动作分类。
- 响应字段归一化或安全裁剪。
- 限流、超时、取消和审计日志。

禁止模型通过 Gateway 绕过专用工具的安全策略。
支付、购买、订阅、下单及代购类能力不注册进清单，因此不存在可供模型调用或审批后执行的 Gateway Handler。

Capability Catalog 不整份注入 System Prompt，也不展开成数百个 Tool Schema。小 N 需要冷门能力时先检索目录；目录结果只返回本次最相关的少量能力。`call_music_api` 再按选中条目的实际参数 Schema 二次验证，不能把 `params: Record<string, any>` 当作已校验输入。

### 5.5 实体解析与上下文池

模型不得猜测业务 ID。系统维护统一实体引用：

```text
当前歌曲       → songId
当前歌手       → artistId
当前专辑       → albumId
当前歌单       → playlistId
最近搜索候选   → entity IDs
最近工具结果   → entity references
```

工具参数应优先支持语义引用：

```json
{
  "songRef": "current",
  "playlistRef": "我的跑步歌单"
}
```

执行前由 Entity Resolver 解析为稳定 ID，并按名称、歌手/专辑限定、当前上下文、流行度、播放历史和画像偏好对候选打分：

- 用户明确提供歌手、专辑或当前上下文能够唯一定位时，直接返回稳定引用。
- 第一候选明显领先时，直接返回稳定引用。
- 多个候选接近且无法可靠判断时，搜索或解析工具返回 `needs_selection`、原因和 2~5 个候选引用，不静默猜测，也不直接弹 UI。
- 小 N 收到 `needs_selection` 后调用 `request_user_selection` Tool；该工具生成 SelectionCard 并等待用户选择，再把选中的稳定引用作为工具结果返回给小 N。
- 小 N 使用所选引用重新调用播放、歌单或其他业务 Tool；该业务调用仍独立经过 M/S 权限判断，选择候选不等于批准执行。

#### `request_user_selection` 交互工具

首版将选择卡注册为内置 Agent Tool。它是小 N 向用户提出结构化选择题的快捷输入方式，不是业务操作 Tool：

```ts
interface RequestUserSelectionInput {
  prompt: string
  mode: 'single' | 'multiple'
  options: [SelectionOption, SelectionOption, ...SelectionOption[]] // 2~5 项
}

type SelectionOption =
  | {
      kind: 'entity'
      optionKey: string
      entityRef: EntityRef
    }
  | {
      kind: 'text'
      optionKey: string
      label: string
      description?: string
    }

interface RequestUserSelectionResult {
  status: 'selected' | 'cancelled' | 'expired'
  selectedOptionKeys?: [string, ...string[]]
  selectedRefs?: EntityRef[]
  reason?: 'user' | 'superseded_by_user_message' | 'app_exit' | 'account_switch' | 'runtime_failure'
}
```

- 实体选项必须来自本轮已完成工具结果或当前 Entity Pool，不能由模型伪造任意网易云 ID；Runtime 根据引用读取名称、歌手、专辑、封面和权益小标等展示字段。
- 文字选项由小 N 提供纯文本 `label` 和可选 `description`，支持“创建新歌单 / 加入现有歌单”一类选择；Runtime 执行长度、重复 key 和控制字符校验，不接受 HTML、Markdown、组件 Props、图片 URL 或可执行回调。
- 同一张卡允许实体与文字选项混排，但总数固定为 2~5。`optionKey` 只用于把选择映射回本次 Tool Call，不是命令名，也不能直接绑定业务 Handler。
- `single` 模式点击任一选项后立即提交，结果数组长度固定为 1。`multiple` 模式允许选择 1~5 项，用户点击“完成”才提交；未选择任何项时“完成”保持禁用。
- 使用场景不限于同名实体消歧，也包括询问用户想听的风格、选择目标歌单、选择整理方案等需要减少输入的对话；它不能代替 ApprovalCard 或危险操作确认。
- 用户点击后的结果语义等同于回答了这道选择题。Tool 不携带待执行动作、回调、后续 Tool 名称或参数模板，也不会自动恢复此前尚未执行的业务动作。
- 该 Tool 属于用户交互能力，不产生音乐/账户副作用，因此不受 M1~M4 审批；它仍计入单 Turn 的 Tool Call 上限，并且同一时刻只允许一个活动选择请求。
- SelectionCard 固定等待 10 分钟；候选与“取消”按钮在有效期内可交互。离开小 N 页面、收起侧栏或最小化窗口继续等待，Renderer 重载后从 Snapshot 恢复卡片和剩余时间。
- 用户点击“取消”时该 Tool 返回 `SELECTION_CANCELLED`，小 N 可以改用其他方式或结束当前步骤；10 分钟到期返回 `SELECTION_EXPIRED`。两者都不执行后续业务动作。
- 用户在等待期间发送新的聊天消息时，以新意图优先：旧 Selection Tool 与旧 Turn 以 `superseded_by_user_message` 取消，再启动新 Turn。应用退出、切换账号或 Runtime 故障同样取消，不跨应用重启恢复。

### 5.6 Dynamic Skill

暂定目录：

```text
app.getPath("userData")/ncx-data/skills/<skill_name>/
├── SKILL.md
├── index.js
└── assets/
```

加载步骤：

1. 扫描 Skill 目录。
2. 解析 YAML Frontmatter 和正文规则。
3. 校验名称、版本、入口和权限声明。
4. 建立 Skill 索引。
5. 根据任务按需注入 Prompt，避免全部加载到上下文。
6. 加载 JavaScript 工具；动态 `import()` 本身不构成安全隔离，Worker/子进程/权限沙箱方案待技术验证。
7. 将工具注册到统一 Tool Registry。
8. 所有调用仍经过 Tool Executor 与权限中间件。

当前设计建议（待确认）：

- 来源：用户手写 + 本地导入；Git 仓库安装与应用内市场列入后续版本。
- 授权：安装时按 SKILL.md 声明一次性同意权限清单；每次实际执行仍经过统一权限中间件，并且只能使用安装后实际注册成功的 Tool 能力。
- 依赖：支持纯 JS 依赖包，安装前展示依赖清单并锁定版本；原生模块依赖暂不支持。
- 命名冲突：与内置工具重名时内置优先，设置页展示冲突清单并允许重命名外部工具。

待确认：Skill 来源信任、签名、更新与卸载规则。

### 5.7 MCP

- NcxMusic 作为 MCP Client 连接外部 Server。
- 将 MCP Server 暴露的工具映射到统一 Tool Registry。
- MCP 工具不能绕过 NcxMusic 的安全分级与审批流程。
- 需要管理 Server 配置、连接状态、工具列表、启停和错误信息。
- 基于官方 `@modelcontextprotocol/sdk` 提供的能力，客户端传输候选为 stdio 与 Streamable HTTP；最终首版范围待技术验证。
- 凭据只保存到 Credential Vault；配置可视化编辑与 `.mcp.json` 导入作为暂定方案。
- 提供 `mcp_manager` Agent Tool，允许小 N 发起 MCP Server 安装。
- 每一次安装都必须生成不可跳过的批准/拒绝卡片，展示 Server 来源、传输方式、启动命令或 URL、声明的能力/工具、环境变量名称和工作目录；安装前信息必须标记为“来源声明”，不能冒充已经过客户端验证的实际能力。
- 只有用户点击“批准”后才能写入配置、安装依赖、启动进程或建立网络连接；主动拒绝、5 分钟过期或任务取消分别返回结构化终态，底层安装逻辑均零执行。
- 首次连接后通过 SDK 获取实际 capabilities 和 tools，与安装前声明做差异检查；未声明或发生变化的工具默认禁用，待用户查看后再启用。
- MCP 安装不支持“本会话允许”或“总是允许”，其他音乐/Shell 权限等级与历史审批策略不得自动放行。
- MCP Server 删除、自动更新、来源信任、签名校验与回滚规则仍待确认。
- 连接关闭时必须显式关闭 SDK Client/Transport，避免遗留 stdio 子进程、请求处理器或未完成任务。

### 5.8 用户画像与长期记忆

画像输入包括：

- 用户创建的全部歌单。
- 用户收藏的歌单，权重低于自建歌单。
- 喜欢的音乐。
- 歌曲加入歌单或收藏的时间。
- 最近更新时间，越新权重越高。
- 播放排行，头部歌曲权重最高。
- 后续可扩展的搜索、跳过、单曲循环和主动删除等行为信号。

画像至少输出：

- 偏好歌手、曲风、语言、年代和情绪。
- 稳定偏好与近期偏好的差异。
- 使用场景倾向。
- 推荐解释所需的证据摘要。
- 可供 Agent 使用的简洁画像 Prompt。
- 每项结论的样本覆盖率、证据引用和置信度。

对外统一称为“音乐人格画像”。它只表达可由音乐数据支持的偏好歌手、曲风、语言、年代、情绪、探索倾向、流行/小众倾向、收听时间和场景变化，不把歌曲偏好包装成真实人格诊断，也不推断医学状态、政治倾向或其他敏感属性。低覆盖或证据冲突的结论必须降低置信度，不能使用确定性文案。

基础信息与画像按网易云用户 ID 分目录或分库保存。画像、对话、摘要和 Working Memory 使用普通 SQLite/JSON，不增加 SQLCipher、独立账户数据密钥或应用级整库加密；依靠本机操作系统用户目录权限隔离。退出登录默认保留，用户可在设置中查看、导出或删除该账号的本地数据。具体自动保留周期仍待确认。

画像构建会在本地扫描并归一化全部已授权输入，但不把完整歌单一次性装入云模型上下文。Local Feature Extractor 先生成分布、时间变化、权重统计、覆盖率和分层代表样本；模型默认只接收这些聚合结果，以及近期、高权重、异常偏好和各主要分组的少量代表歌曲。需要补充证据时，模型可在当前画像任务内调用只读 `get_profile_evidence_page`，按类型、时间段和游标读取下一批归一化证据。该工具只访问当前网易云用户 ID 和当前分析 job，不返回 Cookie、原始数据库文件或其他账号数据，也不能执行音乐写操作；它是画像分析子流程的内部数据提供器，不注册到小 N 的通用 Tool Registry，也不改变“10 个核心业务 Tool + 2 个 Gateway Tool”的主会话范围。

NcxMusic 不主动同步或上传原始账户数据库。使用云端模型 Provider 时，当次对话和上下文选择器挑选出的必要画像/记忆片段仍会作为模型请求的一部分发送；初始化提示和模型设置页必须说明发送范围、Provider 归属及可能产生的 Token 费用。本地模型可避免这部分内容离开设备。

#### 用户画像生命周期

画像状态：

```text
unavailable   // 游客或缺少前置条件
collecting    // 获取并归一化歌单、喜欢与播放排行
ready_local   // 本地特征已完成，等待模型分析
analyzing     // 模型正在形成画像
ready         // 可用于推荐和 Agent Prompt
stale         // 已有画像可用，但需要后台更新
paused        // 保留并继续使用当前画像，但停止扫描和更新
failed        // 初始化或更新失败
```

首次画像不静默采集完整音乐数据，也不自动调用用户的大模型：

1. 登录成功后只获取计算更新条件所需的轻量歌曲数量基线，不进行完整画像分析。
2. 当用户已登录、已配置可用模型且当前账户没有画像时，在小 N 输入框上方显示轻量提示。
3. 提示文案暂定为“让小 N 了解你的音乐口味，为你提供更准确的推荐”。
4. 提示提供“开始分析”和关闭入口；关闭后本次不反复打扰，并允许从设置或小 N 页面重新唤出。
5. 用户点击“开始分析”后才获取完整歌单、喜欢与播放排行，随后调用模型生成画像。
6. 分析提示在原位置切换为进度状态，不使用全页阻塞 Loading。
7. 分析期间小 N 的普通聊天和基础音乐控制仍可使用；离开页面不取消后台任务。
8. 完成后提示变为简短成功状态并自动收起，首页出现“小 N 为你推荐”Section。
9. 失败时保留已采集的归一化数据并提供重试，不重复请求已经成功的数据。
10. 已有画像时先加载当前版本；启动时只获取变化评分所需的轻量计数，达到阈值后在输入框上方提示用户是否更新，不静默调用模型。

已有画像时，应用直接载入当前版本。是否需要更新由音乐库变化评分决定，不按固定日期静默重算。

#### 画像变化评分

首次登录记录轻量基线；首次画像成功后保存更完整的分析基线。当前确认权重：

```text
我喜欢的歌曲变化       × 1.5
自建歌单的歌曲变化      × 1.0
收藏歌单的歌曲变化      × 0.0
```

当前计算方式：

```text
changeScore = likedSongChanges × 1.5
            + createdPlaylistSongChanges × 1.0

updateThreshold = 30
```

当 `changeScore >= updateThreshold` 时，不直接静默调用模型，而是在小 N 输入框上方提示“你的音乐口味有了新变化，是否更新画像”。用户确认后进行增量采集与重新分析。

变化量以歌曲 ID 去重；同一首歌同时属于“我喜欢”和自建歌单时只取最高权重 1.5。删除后重新添加、歌单间移动和批量导入如何计数仍待确认。

#### 画像查看与用户控制

- 个人信息页提供“音乐人格画像”入口，展示当前画像版本、更新时间、数据覆盖范围、主要偏好、近期变化、证据和置信度。
- 用户可以纠正标签、隐藏不准确结论或补充自己的偏好说明；这些显式修正以独立 override 保存，优先级高于模型推断，后续重算不得静默覆盖。
- 纠正只影响 NcxMusic 的画像、推荐和 Agent 上下文，不回写网易云歌单、喜欢或账户资料。
- “暂停更新”保留当前画像并允许推荐和 Agent 继续读取，但停止启动时的变化扫描、完整/增量采集和云模型调用；用户恢复后先重新计算变化基线，再决定是否提示更新。
- “删除画像”删除当前账号的本地画像、分析中间特征、代表样本缓存和用户 override，不删除网易云数据、聊天历史或基础账号信息；删除前使用 AlertDialog 明确范围。
- 删除后回到未初始化状态，用户可重新点击“开始分析”；“重新生成”则在保留旧版本可回退到失败前的前提下启动新 job，成功后原子替换。

### 5.9 双权限系统

#### 音乐操作权限

下表只约束小 N 发起的 Tool Call；用户在界面中的直接操作不经过 Agent 权限审批。

| 操作类别 | 典型动作 | M1 | M2 | M3 | M4 |
| --- | --- | ---: | ---: | ---: | ---: |
| 播放与队列 | 播放/暂停、上下首、进度、音量、播放模式、队列插入/移除/排序/替换/清空 | 审批 | 免审 | 免审 | 免审 |
| 收藏与歌单日常管理 | 喜欢/取消喜欢、收藏/取消收藏、签到、创建/重命名歌单、增删/排序歌单歌曲 | 审批 | 审批 | 免审 | 免审 |
| 公开社交 | 发表评论/删除评论、评论点赞、关注/取消关注 | 审批 | 审批 | 免审 | 免审 |
| 高影响音乐与账户 | 删除整个自建歌单、修改头像/昵称/资料、手机等账号绑定、退出登录 | 审批 | 审批 | 审批 | 免审 |

M4 是最高风险等级，表示已注册音乐能力均可免审。用户在 MusicSafetyControl 中选择后立即生效并持久化，不弹 AlertDialog、不要求二次确认，也不在应用重启后重复提示；控件本身持续显示当前等级。M4 不能产生新的 Tool 或 Action，也不影响独立的 MCP 安装审批。支付、购买、订阅和下单未注册为首版能力，不属于任何 M 等级。

#### 命令执行权限

| 等级 | 已确认方案 |
| --- | --- |
| S1 | 所有 Shell 命令均需审批。 |
| S2 | 只有命令白名单与参数规则明确判定为只读的搜索、查看和状态检查自动执行；写入、联网、启动外部进程和其他未知命令均审批。 |
| S3 | 用户明确授权工作区内的常规文件读写、构建、测试和开发命令自动执行；删除、外部联网安装、工作区外访问和提权均审批。 |
| S4 | 用户授权工作区内所有通过 S4 结构、参数与作用域审查的 Shell 命令自动执行，包括联网和依赖安装。可执行范围仍由 Shell Tool 契约、授权工作区与最小进程环境决定。 |

设置中另提供“关闭 Shell Tool”，关闭后 Agent 看不到 Shell Tool，不能通过提高 S 等级重新启用。S1~S4 与音乐 M1~M4 是两套独立设置。

#### 判断与审批流程

```text
Tool Call
  → 参数 Schema 校验
  → resolveRegisteredCapability(tool, action, capabilityId)
  ├─ unavailable: 返回 CAPABILITY_UNAVAILABLE，不创建审批
  └─ registered
  → classifyOperation(tool, action, args)
  → evaluatePolicy(operation, musicLevel, shellLevel)
  ├─ allow: 执行底层 handler
  ├─ ask: 创建审批请求并挂起
  └─ deny: 不执行并返回结构化拒绝
```

审批请求必须包含操作名称、影响对象、关键参数、风险解释和可选过期时间。Utility Process 产生审批事件，经 Main/Preload 的受限 IPC 桥推送给 Renderer；批准/拒绝响应沿同一路径返回并再次进行 Schema、任务 ID 和状态校验。首版不为内部通信启动 SSE 或 localhost HTTP 服务。

其他审批行为如下，其中未标注部分继续逐项确认：

- 已确认：所有审批卡片只显示“批准”“拒绝”，批准只对当前规范化 Tool Call 生效，不创建会话级、永久或历史豁免；长期权限只能通过音乐/命令安全等级调整。
- 已确认：ApprovalCard 没有关闭按钮，固定 5 分钟过期且不可配置。离开页面、收起侧边栏和最小化窗口继续等待；Renderer 重载恢复剩余时间。应用退出、账号切换和 Utility Process 故障立即取消，不跨应用恢复。
- 已确认：用户主动点击“拒绝”返回 `USER_REJECTED`，超时返回 `APPROVAL_EXPIRED`，生命周期取消返回 `APPROVAL_CANCELLED`；三者都不能执行底层逻辑。
- 能力是否存在先由 Tool Registry、Gateway Capability Catalog、工作区授权和进程最小环境确定；权限等级不能创造未注册能力。Credential Vault、权限策略写入口等没有 Tool Handler 的内部能力不会进入模型可见 Schema。
- MCP 安装同样使用上述生命周期，并继续保持任何安全等级都不能免除审批。

### 5.10 工具执行与交互卡片

工具展示卡片至少包含：

- 工具名称及类别。
- 当前状态：排队、运行、成功、失败、已取消。
- 对用户可理解的参数摘要。
- 执行耗时和结果摘要。
- 可展开的技术详情。

审批卡片至少包含：

- Agent 想做什么。
- 将影响哪些歌曲、歌单、账户数据或文件。
- 风险等级和原因。
- 两个且仅两个操作按钮，文案固定为“批准”“拒绝”；不显示“批准本次”“允许会话”“总是允许”等变体。
- 不提供关闭图标；展示轻量剩余有效时间，并防止重复提交。过期、取消和拒绝后按钮不可再次点击。
- MCP 安装卡片只提供当次批准/拒绝，不显示任何记忆授权入口。

选择卡至少包含：

- 小 N 当前需要用户选择什么，以及为什么无法唯一确定。
- 2~5 个可点击选项，可混排音乐实体与普通文字选项；音乐实体展示封面、名称、歌手、专辑及 VIP/付费小标，文字选项展示标题和可选简短说明。
- 明确的“取消”按钮；多选模式额外提供“完成”按钮并在至少选择一项后启用。固定 10 分钟有效，不能使用 ApprovalCard 的 5 分钟计时。
- 候选点击只完成 `request_user_selection` Tool，不直接播放、收藏、修改歌单或批准任何后续动作。
- 已选择、取消或过期后卡片保留终态并禁止重复提交；Renderer 重载只恢复仍有效的活动选择。

ApprovalCard 与 SelectionCard 都以内联 Agent 卡片呈现，但不得共用业务语义：前者决定是否授权一个已经确定目标的 Tool Call，后者只帮助小 N 确定目标。一次意图可能先后出现选择卡和审批卡。

#### 播放操作提示与事件日志

播放器操作采用“结构化事件日志 + 轻量用户提示”两层设计，两者用途不同：

- Action Journal 供小 N、调试和状态协调查询。
- Toast/Message 供用户即时感知操作来源。

事件至少包含：

```text
eventId
actor          // user | agent | system
action         // play | pause | next | previous | queue_add | queue_remove | queue_replace ...
targetRefs
beforeRevision
afterRevision
createdAt
result
toolCallId
```

规则：

- 用户直接播放控制始终即时生效，不等待 Agent。
- 小 N 执行音乐操作时读取播放器最新状态，不使用规划阶段的过期队列快照。
- 用户与小 N 在接近时间操作时不弹冲突模态框，以最终播放器状态为准。
- 小 N 的成功操作显示轻量提示，例如“小 N 为你播放了《晴天》”。
- 大范围队列变更提示影响数量；首版不提供播放队列撤销入口。
- 小 N 可通过 `get_recent_player_actions` 查询最近事件，理解用户是否刚刚手动切歌或调整队列。
- 高频播放进度不写入 Action Journal；只记录具有语义的状态变化。
- 日志保留数量和时间待确认，避免无限增长。

### 5.11 Shell Tool

- Windows 固定启动 PowerShell，并使用 `-NoProfile -ExecutionPolicy Bypass`。
- macOS 使用 `/bin/zsh`。
- Linux 优先 `/bin/zsh`，回退策略待确认。
- Shell Tool 必须声明工作目录、超时、环境变量策略和输出上限。
- 命令执行必须支持取消、标准输出/错误流式返回和退出码。
- 敏感信息脱敏、环境变量访问、路径范围及危险命令策略待确认。
- 已确认的原则只有“全部由纯函数判定，LLM 不参与权限判断”；命令白名单、危险参数模式和默认工作目录属于待验证的实现建议。

### 5.12 语音快捷操作

当前目标交互：

```text
按住 Alt+Space
  → 显示声波浮窗
  → 聆听中
松开
  → 结束录音
  → 浮窗直接关闭
  → 轻提示显示识别中
  → 识别成功后交给 Agent
  → 轻提示返回执行成功或失败
  → 若需要审批/选择，通知用户点击后打开小 N 卡片
```

浮窗根据 `screen.getPrimaryDisplay().workArea` 定位在工作区底部附近，避开 macOS Dock 与 Windows 任务栏。

已确认的交互边界：

- 按住 `Alt+Space` 唤起，松手后关闭小组件。
- 聆听期间不暂停歌曲，通过瞬时音频增益将音乐输出降到原音量约 20%；不覆写用户保存的音量设置。
- 松手后只在歌曲未切换且期间没有新的暂停/播放/切歌意图时恢复原输出。
- 声波组件只展示“聆听中”；“识别中”和 Agent 执行结果使用独立轻提示，不再给声波组件增加“小 N 回复中”状态。
- 首版只调用云端 ASR，不下载或运行本地语音模型，也不依赖 Windows/macOS 原生语音识别。
- Cloud ASR Adapter 将录音转换为供应商请求并把识别文本归一化后交给 Agent；网络或服务不可用时返回明确错误，不存在本地离线回退。
- 云端识别默认且仅尝试复用当前 Agent Provider Profile 的 Base URL、API Key、自定义 Headers 和当前模型能力，不要求用户再配置第二套语音服务，也不自动切换备用供应商。
- Provider Adapter 按当前协议探测或调用模型的语音输入/转写能力；能力状态记录为 `unknown | supported | unsupported`。切换模型、Base URL、协议或凭据后立即使旧探测结果失效。
- 当前能力已标记为 `unsupported` 时，不启动录音和上传，直接提示“当前大模型不支持语音识别（ASR）”。状态为 `unknown` 时允许首次调用验证；供应商明确返回不支持后缓存结果并显示相同提示。
- 首次启用语音时必须披露音频将发送给当前大模型 Provider、本地不留存，以及云端处理和留存受该 Provider 政策约束。
- 录音数据只在内存中存活到上传与识别结束；成功、失败、超时或取消都立即释放，不落盘、不进入聊天记录或日志。应用只能承诺本地处理边界，云端留存以当前 Provider 的政策为准。
- 识别中、执行成功或失败通过轻提示展示。需要 ApprovalCard 或 SelectionCard 时不自动激活主窗口或抢夺键盘焦点；先发出“需要你确认”的通知，用户点击后再打开小 N 并定位对应卡片。
- 全局快捷键默认是 `Alt+Space`，设置页允许重新录制组合键。保存前先尝试注册；冲突或平台拒绝时保留旧快捷键并显示原因，不抢占其他应用、不静默改成另一组合。
- Agent 输入区始终提供麦克风按钮。全局快捷键不可用时，用户仍可在应用内按住该按钮完成相同的录音流程。

待确认事项：

- 各已支持模型协议如何探测并调用语音输入/转写能力，属于 Provider Adapter 技术验证，不新增独立 ASR Profile。
- 实现全局按键抬起监听所需的原生能力与 macOS 权限提示。

### 5.14 首次引导与模型配置

#### 首次引导目标

首次引导不是功能说明书，而是让用户在较短时间内理解三件事：NcxMusic 是什么、小 N 能做什么、如何让小 N 开始工作。

#### 暂定引导流程

```text
01 欢迎
   Logo + NcxMusic + 一句话价值主张

02 认识播放器
   高颜值播放、歌词、歌单与个性化推荐的视觉演示

03 认识小 N
   动画演示：唤醒浮窗 → 说出“下一首” → 小 N 调用工具 → 完成切歌

04 网易云账户
   打开官方网页登录；允许跳过，跳过后自动进入游客模式

05 数据与安全
   简述本地记忆、音乐/命令双权限和 API Key 的本地安全存储

06 配置模型
   选择厂商预设或自定义服务 → 填写 API Key → 拉取模型 → 能力测试

07 完成
   进入应用；也可以跳过模型配置后进入
```

动效资产优先使用 WebM、Lottie 或程序动画，不把大体积 GIF 作为主要方案。引导页支持返回、下一步、跳过和以后重新打开。

#### 未配置模型的行为

- 音乐播放器功能仍可正常使用。
- 小 N 导航入口保持可见，不伪装成不可用或隐藏功能。
- 进入小 N 后展示未配置空状态、用途说明和“前往模型设置”。
- 需要 Agent 的语音命令给出相同引导，不静默失败。
- 用户配置并验证成功后，空状态自动切换为正常会话。

#### Provider Profile

每个模型服务保存为一个独立 Profile：

```text
providerId
displayName
protocol              // 首版为 openai-chat-completions
baseUrl
modelsPath
chatCompletionsPath
credentialRef         // 只引用 Credential Vault，不保存明文 Key
modelId
customHeaders
capabilitySnapshot
lastVerifiedAt
```

首版提供常见厂商预设。预设仅填写厂商名、官方地址、接口路径、图标和兼容规则，不内置用户密钥。

自定义服务允许填写中转站或兼容服务的名称、Base URL、API Key、模型 ID和必要的自定义 Header。API Key 不进入普通设置文件、Renderer 持久化、日志、Prompt 或远程配置服务。

#### 模型列表不能只靠写死

不存在一个能够可靠覆盖所有官方厂商、中转站和本地服务的统一模型目录。采用四层策略：

1. **内置最小预设**：随版本提供稳定厂商入口和接口规则，保证离线时能填写。
2. **远程 Provider Manifest**：从 NcxMusic 官方 GitHub 仓库读取有版本号和签名/校验值的静态清单，用于更新厂商地址、弃用信息和能力提示；该服务永远不接收用户 API Key。
3. **实时模型枚举**：用户填写凭据后，优先调用厂商/中转站的 Models Endpoint，获得当前账号真正可用的模型 ID。
4. **手动模型 ID**：服务不支持模型枚举、返回失败或中转站做了裁剪时，用户始终可以手动填写。

OpenAI 标准接口通常通过 `GET /v1/models` 返回当前凭据可用的模型；DeepSeek 官方当前提供 `GET /models`。具体路径由 Provider Preset 决定，不通过盲目向第三方域名尝试多个地址来探测。

模型列表通常只提供模型 ID、所有者等基础信息，不能可靠证明是否支持 Tool Call、流式输出或特定参数。因此保存前执行分层测试：

1. 连接与鉴权测试。
2. 模型列表或指定模型可访问测试。
3. 最小流式对话测试。
4. 无副作用的最小 Tool Call 测试。

只有通过 Tool Call 测试的模型才能标记为“小 N 已验证”。失败时允许保存配置，但必须显示“不支持 Agent 工具或尚未验证”，避免用户配置了只能聊天、不能控制播放器的模型。

#### 首版协议范围（已确认）

为覆盖主流用户同时控制维护成本，首版只提供三个一等协议适配器：

| 协议适配器 | 用途 | 首版结论 |
| --- | --- | --- |
| OpenAI Chat Completions Compatible | OpenAI、大多数国内厂商、中转站、OpenRouter、兼容的本地服务 | 首版支持，作为默认兼容层 |
| Anthropic Messages | Claude 官方 API，原生 content blocks、tool use/tool result 和上游流式事件 | 首版支持 |
| Google Gemini `generateContent` | Gemini 官方 API，原生 parts、functionCall/functionResponse、流式与后续多模态能力 | 首版支持 |

厂商策略：

- DeepSeek、通义千问、Kimi、智谱等优先使用其 OpenAI 兼容入口，不为每个厂商单独维护 Adapter。
- 中转站默认使用 OpenAI 兼容 Adapter，并允许自定义 Base URL、路径和 Header。
- Ollama、LM Studio 等本地服务首版优先走 OpenAI 兼容模式，不维护专属协议。
- AWS Bedrock、Azure AI、Vertex AI、Cohere、Mistral 等原生协议暂不进入首版；有真实用户需求后再评估。
- OpenAI Responses API、Gemini Live API 等增强协议作为后续能力，不阻塞基础 Agent 上线。

所有 Provider Adapter 最终转换成统一内部事件：文本增量、思考增量、工具调用开始/参数增量/完成、用量、结束原因和错误。这样 Agent 主循环与权限系统不需要理解厂商差异。

#### 设置页模型管理

- 支持新增、编辑、复制、删除和启停多个 Provider Profile。
- 指定当前 Agent 使用的默认 Profile 与模型。
- 展示连接状态、最后验证时间、延迟和能力标签。
- 支持刷新模型列表和手动输入模型 ID。
- 修改 Base URL 或 API Key 后自动将旧能力测试标记为失效。
- 删除正在使用的 Profile 前要求用户选择新的默认配置或确认停用 Agent。

## 6. API First 开发规则

全量清单、执行顺序、最低调用次数、多变量矩阵、参数血缘、字段类型、未知字段、安全边界与报告模板，以 [NcxMusic-API-First-Full-Audit-Playbook.md](../api/NcxMusic-API-First-Full-Audit-Playbook.md) 为唯一执行规范。

API First 的范围是锁定依赖版本中由 exports、module、类型声明、官方文档和官方测试共同发现的全部 API，不按首版页面裁剪。每个接口必须按以下顺序进入开发（每个 API 先建立专用测试脚本，多次调用覆盖不同参数与边界分支，确定返回数据格式）：

1. 在隔离测试环境发起真实请求。
2. 保存脱敏响应样本。
3. 分析必填、可空、条件出现、分页和错误字段。
4. 强制比较未登录、游客、普通登录，并按适用性覆盖 VIP、已购、资源归属、空数据、分页、限流和异常响应。
5. 定义请求与响应 Schema。
6. 转换为内部统一实体。
7. 加入缓存、字段池和请求编排。
8. 封装业务 Service、登记 Capability，并映射到核心 Tool 或冷门 API Gateway。
9. 编写契约测试。
10. 最后接入 UI。

未经字段分析的 API 不直接进入正式业务代码。

### 6.1 音质 API First 矩阵

- 对 `/song/url/v1` 的 9 个 `level` 分别建立请求样本，调用时明确 `unblock=false`；上游模块注释表明 `unblock=true` 时设置音质不生效。
- 账户覆盖游客、已登录非 VIP、VIP 和已购买资源；歌曲覆盖仅标准/较高、极高、无损、Hi-Res、超清母带、三种空间格式、VIP、付费、试听和不可播样本。
- 记录每次请求的 `url`、`level`、`br`、`type`、`size`、`fee`、`freeTrialInfo`、状态码与错误字段，区分“上游自动降级”、“空 URL”和“需要本地重试低档”。
- 对照 `/song/detail` 的 `h`、`m`、`l`、`sq`、`hr` 与 `privileges`，但不假设这些字段可完整表达空间格式或账户实际播放权限。
- `dolby` 额外覆盖设备差异，并按官方文档验证 Cookie 附带 `os=pc` 时返回的 URL、码率和实际格式。
- 上游自动降级行为未实测前，不把“请求成功”等同于“按请求档位播放”；始终读取响应的实际 `level` 和媒体字段。

### 6.2 封面尺寸 API First 矩阵

- 从歌曲、专辑、歌单和歌手接口各选取多组真实图片 URL，分别请求 `96y96`、`160y160`、`320y320`、`640y640` 和 `1024y1024`。
- 对每个样本记录 HTTP 状态、Content-Type、实际像素尺寸、文件体积、缓存响应头和加载耗时，验证参数是否确实生效，而不是只检查 URL 字符串。
- 覆盖原 URL 已有查询参数、已有 `param`、空 URL、非网易云图片 URL、失效图片、目标尺寸大于原图和网络失败场景。
- 验证同一原图不同尺寸的缓存键不会碰撞，并测量密集歌曲列表与推荐 Section 的首屏请求数量、传输体积和解码占用。
- 测试通过后只由图片 URL Adapter 暴露语义变体；API 原始 URL 继续进入标准实体字段池，派生 URL 不作为新的实体字段。

## 7. 全局字段池与请求编排

系统需要建立标准实体：

- `User`
- `Song`
- `Artist`
- `Album`
- `Playlist`
- `Comment`
- `PlaybackState`

多个 API 返回同一实体时，通过稳定 ID 合并字段，而不是重复维护。例如较早请求已经获得用户名，后续接口中的同名字段可以忽略，除非后续响应具有更高新鲜度或权威级别。

字段池和按请求顺序复用已有字段的原则已确认。以下“权威 + 新鲜度 + 完整度”合并规则是待 API 样本验证的暂定实现，至少考虑：

- 数据来源优先级。
- 请求时间和字段新鲜度。
- 字段是否完整。
- 是否允许空值覆盖。
- 登录账户数据和公共数据的权威差异。

缓存需要分级、离线标记、Section 级重试与降级，但用户数据 24 小时、首页推荐 30 分钟、搜索建议 1 小时等具体 TTL 只是建议值。应用打开后的请求顺序、失效条件和手动刷新入口仍待确认。

## 8. 暂定系统架构

```text
Renderer/UI
  ├─ 播放器与业务页面
  ├─ Agent 侧边栏
  ├─ Tool Call / Approval 卡片
  └─ Voice Overlay
          │ 受限 IPC / MessagePort
       Preload Bridge
          │
Electron Main
  ├─ Window / Session / Credential Vault
  ├─ IPC Gateway（Schema 校验与事件裁剪）
  └─ Utility Process Supervisor
          │ postMessage / MessagePort
          ▼
Agent Utility Process
  ├─ Handwritten Agent Runtime / Context Builder
  ├─ Tool Registry / Entity Resolver
  ├─ Deterministic Policy Engine / Approval Coordinator
  ├─ NeteaseCloudMusicApiEnhanced / Music API Adapters
  ├─ MCP Client Manager / Dynamic Skill Loader
  ├─ Shell Executor
  └─ Profile / Memory / Audit Stores
```

Main 使用 `utilityProcess.fork()` 管理 Agent Utility Process。跨进程消息采用可版本化的统一事件信封，至少包含 `protocolVersion`、`taskId`、`eventId`、`sequence`、`type` 和经过裁剪的 `payload`。模型供应商的 SSE、chunked stream 或其他上游流式格式只在 Provider Adapter 内解析，Renderer 只接收归一化增量事件。

播放控制采用请求/结果式命令通道：Agent Tool 先经确定性权限中间件，再由 Utility Process 的 `PlayerCommandGateway` 将带 `commandId`、`issuedBy`、`expectedRevision` 和类型化 `payload` 的命令发往 Renderer。Renderer 根层常驻 `PlayerCommandBridge` 交给唯一 `PlaybackCoordinator` 执行，再回传成功、拒绝、过期、失败或不可用结果及最新播放快照。Tool 必须等待结果或超时，不得把“已发送”当作“已执行”。

`PlayerCommandBridge` 不放在 `AgentChat.vue` 或任何路由页内；小 N 侧边栏关闭时仍能执行语音和后台播放命令。Pinia 可作为 Vue 响应式读模型和命令适配层，但不直接通过 DOM ID 操作 `<audio>`，也不在 `audio.play()` 完成前猜测成功状态。页面音乐数据请求则通过 Preload 暴露的类型化 Music Gateway 进入 Utility Process 的同一 Music Service；Agent Tool 在 Utility Process 内直接复用该 Service，Renderer 不直接访问 NeteaseCloudMusicApiEnhanced。

Utility Process 崩溃或退出时，Main 负责更新 Agent 可用状态、取消未决审批、清理 MessagePort 并按待确认的重启策略恢复；应用退出时显式终止 Utility Process 及其 MCP/Shell 子进程。Renderer 重载后重新握手并获取任务快照，不能复用失效端口。Utility Process 只接收显式构造的最小环境变量，不继承不必要的 Main 进程环境。

安全边界原则：Renderer 不直接获得 Node.js、Shell、文件系统、网易云凭据或任意网络访问能力；所有特权操作通过最小化桥接接口进入主进程或独立本地服务。

## 9. 非功能需求

### 9.1 安全

- 权限判断确定且可测试。
- 所有工具调用具备审计记录。
- Dynamic Skill 与 Shell 不在 Renderer 运行。
- 凭据不得进入模型上下文、日志或工具展示卡片。
- 拒绝操作必须保证底层副作用未发生。
- 高风险权限切换应有明确视觉反馈。

### 9.2 可靠性

- Agent 工具支持超时、取消和失败恢复。
- 审批等待不阻塞其他会话或播放器运行。
- API 局部失败不导致整个画像构建失败。
- Skill 或 MCP Server 崩溃不能拖垮主播放器。

### 9.3 性能

- 播放控制不依赖模型返回。
- Agent 页面加载不应被完整画像计算长期阻塞。
- 画像生成支持阶段性结果和后台增量更新。
- Prompt 仅加载当前任务需要的 Skill 与记忆。

### 9.4 隐私

- 明确哪些音乐数据发送给模型服务。
- 原始 SQLite、画像文件和账户目录不上传；云模型只接收完成当前任务所需的最小上下文片段。
- 用户能够查看、导出和删除本地记忆。
- 日志、语音和对话的具体保留期限仍需单独确认。

- D-303（已确认）：首次完整画像由小 N 输入框上方提示触发，不静默执行；启动时用轻量计数检查变化，喜欢歌曲权重 1.5、自建歌单歌曲权重 1、收藏歌单不计，累计变化超过 30 后提示用户更新。
- D-304（已确认）：用户可以查看、纠正、隐藏、删除、重新生成和暂停画像更新；显式纠正优先于模型推断且不回写网易云，暂停保留当前画像供推荐与 Agent 使用但停止扫描和更新。
- D-305（部分确认）：画像、对话和基础信息使用普通 SQLite/JSON，不做整库加密；退出登录默认保留并允许显式删除。具体自动保留期限待确认。
- D-306（已确认）：本地处理全部授权音乐数据，云模型默认只接收聚合特征和分层代表样本；需要更多证据时通过当前画像任务限定的只读分页工具按需读取，不一次性上传完整歌单。

### P1：语音

- D-401（已确认）：首版只使用云端 ASR，不集成本地、离线或操作系统原生识别方案；云服务不可用时明确失败，不提供本地回退。具体云端 Provider 与协议继续确认。
- D-407（已确认）：云端 ASR 默认且仅复用当前 Agent Provider Profile 和当前模型能力，不配置或自动切换第二套 ASR 服务；当前模型不支持时停止上传并提示“当前大模型不支持语音识别（ASR）”。
- D-402（已确认）：松手后声波组件立即关闭，识别中和执行结果使用轻提示；需要审批或选择时先通知但不抢焦点，用户点击后打开小 N 和对应卡片。
- D-403（已确认）：首版不提供 TTS，语音能力仅包含 ASR 识别和指令输入。
- D-404（已确认）：全局语音快捷键默认 `Alt+Space` 且允许修改；注册失败或冲突时不抢占、不静默替换，保留旧绑定并提示改键，应用内麦克风按钮作为固定回退入口。
- D-405（已确认）：原始录音只在内存中保留到云端上传与识别结束，成功、失败、超时或取消后立即释放，不落盘、不写入聊天或日志；云端留存边界按 Provider 政策披露。
- D-406（已确认）：`Alt+Space` 聆听期间将音乐临时降到原输出约 20% 而不暂停；松手后条件恢复，不覆盖期间新的播放意图。

### P2：API、数据与缓存

- D-602（已确认）：为每个 API 创建专用测试 JS，按接口类别满足最低调用次数和“三个有差异稳定样本”停止规则；响应、字段类型、错误、参数血缘和副作用验证均写入统一报告。
- D-603（部分确认）：建立全局字段池并按启动请求顺序复用字段；权威 + 新鲜度 + 完整度合并算法待 API 样本验证。
- D-604（待确认）：用户、歌单、首页推荐和搜索建议分别采用什么 TTL、刷新和离线策略？

- D-606（部分确认）：`/song/url/v1` 文档列出 9 个音质 level，但在线文档与仓库 TypeScript 枚举存在 `higher`/`dolby` 差异；九档请求、实际降级、账户权益、特殊格式和字段映射待 API First 样本验证。
- D-607（已确认）：网易云封面按 `thumbnail`、`compact`、`card`、`feature`、`hero` 五档语义尺寸加载，推荐与详情使用高精度变体，密集列表使用小图；参数与缓存行为仍须按 API First 矩阵实测。
- D-608（已确认）：登录态是全局强制测试维度：所有可调用接口至少比较未登录、游客和普通登录；媒体、权限、账户和写操作再按 VIP、已购、资源归属及状态跑关键完整矩阵，普通附加变量可采用 pairwise。
- D-609（已确认）：接口参数优先复用上游测试结果并记录生产接口、case 与 JSONPath；未知字段不得猜测或丢弃，支付和不可逆接口仍进入清单，但默认只做静态分析与安全负向探测，不改变首版不注册支付能力的范围。

## 13. 暂定里程碑

暂定拆分方向，不代表已确认开发顺序：

1. 技术验证：登录/API、播放链路、模型 Tool Call、权限挂起、快捷键。
2. 基础播放器与统一数据模型。
3. 手写 Agent Runtime 与音乐工具。
4. 用户画像、记忆与推荐闭环。
5. 双权限按钮、执行卡片与审批卡片。
6. 语音浮窗与 ASR 技术验证；首版不包含 TTS。
7. Dynamic Skill 与 MCP 管理。
8. 双平台视觉适配、稳定性和发布。

## 14. 完成定义

本需求阶段完成需满足：

- P0、P1、P2 问题全部有明确结论；当前尚未完成，见第 11 节待确认项。
- MVP 和后续版本边界清晰。
- 每项核心功能具备可测试的验收标准。
- 权限矩阵不存在模糊动作。
- 数据、进程、信任和网络边界明确。
- API 清单及测试优先级确定。
- 关键技术风险已有验证任务和退出条件。
